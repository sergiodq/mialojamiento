# Roles y permisos Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Completar superadmin y agregar soporte con consulta global y edición mínima protegida por Firestore.

**Architecture:** Capacidades de consulta separadas de administración. Perfil canónico y validación de reglas para impedir escalamiento desde el cliente.

**Tech Stack:** JavaScript, Firebase Authentication, Firestore, node:test, Firebase Emulator.

**Spec:** docs/superpowers/specs/2026-11-21-roles-design.md

## Global Constraints

No desplegar ni modificar datos reales. No borrar documentos de negocio. Solo superadmin asigna roles globales. Soporte edita únicamente campos explícitos. No ampliar alcance de admin/recepción.

## Review Focus

- Admin modifica su espejo o registra un rol global: denegar.
- Usuario dado de baja con sesión válida o espejo obsoleto: denegar.
- Soporte mezcla notas con cambios críticos: denegar toda la escritura.
- Reserva de otra empresa se mueve hacia una propia: denegar.
- Registro/auto-reparación altera propiedades o reactiva una baja: denegar.
